# Temporary recording demo hosting

The owner selected Vercel Hobby and Supabase Free for an entirely noncommercial recording demo. Vercel's terms permit personal or noncommercial Hobby use. Keep Docker Compose as the full local build and test environment. This proposal documents a potential hosted demo. The provider documentation was checked on November 21, 2026. Hosted compatibility and operation are untested. [Vercel Terms of Service](https://vercel.com/legal/terms) · [Supabase pricing](https://supabase.com/pricing)

## Proposed request and data flow

1. Serve the Vite UI and Fastify HTTP API on one Vercel origin. Vercel Services is in beta on Hobby and can route `/api/*` to Fastify and other requests to Vite. Enable Vercel Authentication with **All Deployments** for preview and production URLs, with no shareable links or public exceptions. Hobby allows one external user per account through access requests. Keep Better Auth on the same origin with secure cookies, no open sign-up, and the app's own role, suppression, and export checks. Use the Vercel Team setting to opt out of model training before uploading project content. [Services routing](https://vercel.com/docs/services/routing) · [Services availability](https://vercel.com/docs/services) · [Deployment Protection](https://vercel.com/docs/deployment-protection#all-deployments) · [Vercel Authentication](https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication#access-requests) · [Vercel Terms of Service](https://vercel.com/legal/terms)
2. Have the API persist a run, task, and outbox entry in Supabase Postgres. Run the TypeScript scheduler, outbox dispatcher, and pg-boss worker on the recording machine. The worker polls the database over outbound TLS and invokes the authenticated Scrapling service on the local private network. The collector keeps its controlled egress and has no database or object storage credentials. The worker validates and commits results and safe evidence projections. The hosted API reads progress and results through the database. The laptop needs no public port or tunnel. Closing it pauses execution until the worker resumes. [Job engine and collection contracts](requirements/02_Land_Intelligence_Implementation_Plan.md#6-job-engine-and-scheduler-implementation)
3. Keep raw evidence and browser state local. Record with labeled synthetic data. The hosted evidence panel reads safe excerpts and references from Postgres. For synthetic downloads the worker can upload approved files to a private Supabase Storage bucket and record the object key. The API checks the session, role, scope, suppression, and expiry at download time, then streams the object through the same origin. Keep storage credentials on the server and worker. Project S3 keys bypass bucket RLS, so keep them confined to a dedicated disposable demo project and enforce authorization before each read. Use private, uncached attachment responses. [Private buckets](https://supabase.com/docs/guides/storage/buckets/fundamentals#private-buckets) · [S3 key permissions](https://supabase.com/docs/guides/storage/s3/authentication#s3-access-keys)

## Scoped API and MCP access

Use a protected Preview deployment for recording. Browser users sign in to Vercel and Skyscrape. For the REST client and the local MCP stdio bridge, obtain a short-lived `VERCEL_OIDC_TOKEN` on the recording machine with the authorized Vercel CLI linked to the demo project. Vercel documents `vercel env pull` for obtaining the development token. Keep any downloaded environment file outside Git with restricted access. Trusted Sources is available on Hobby and defaults to allowing a project's Development token to reach its own Preview deployment. Verify that rule on the demo project. [Local OIDC token](https://vercel.com/docs/oidc/access-other-services#in-local-development) · [Trusted Sources](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/trusted-sources#default-access)

Send the token in `x-vercel-trusted-oidc-idp-token` and send a separate scoped Skyscrape API key using the application's API key scheme. Have the bridge add the Vercel header only on requests to the exact HTTPS demo origin and reject redirects. Keep both credentials out of tool outputs, logs, and browser bundles. Fastify checks key scope, record authorization, and suppression for REST and MCP. The same-project Development rule covers Preview. Any expansion to Production requires separate approval. [Vercel request header](https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/trusted-sources#how-it-works) · [Skyscrape API and MCP contracts](requirements/02_Land_Intelligence_Implementation_Plan.md#5-api-and-mcp-contracts)

## Database and free-tier checks

- **Database setup.** Enable PostGIS as the project administrator and check its schema and installed version. Supabase enables it in the `extensions` schema in its example. Verify that the app's spatial functions, types, and indexes resolve there. Keep the [local bootstrap](../infra/compose/db/init/10-bootstrap.sql) for Compose. Hosted Supabase uses a managed `postgres` database and an administrator without unrestricted superuser access. Apply app migrations with a separate migrator and scoped grants for the API and worker. Initialize or migrate the pg-boss schema with the migrator and prove the worker can use it with narrowed grants and automatic migrations disabled. Turn off the Supabase Data API if unused and verify that anonymous REST and GraphQL requests cannot reach app or queue tables. Supabase's hosted release notes document PostgreSQL 15 and 17. Check `SHOW server_version` and the PostGIS version on the actual project, then run migration and queue checks before relying on compatibility with the local PostgreSQL 18 baseline. [PostGIS setup](https://supabase.com/docs/guides/database/extensions/postgis) · [Managed role limits](https://supabase.com/docs/guides/database/postgres/roles-superuser) · [Data API controls](https://supabase.com/docs/guides/api/securing-your-api#disable-the-data-api) · [Hosted Postgres release notes](https://supabase.com/changelog/postgres-15-19-17-11-breaking-changes)
- **Connections.** Use Supabase's direct IPv6 endpoint for migrations and the long-lived pg-boss worker where reachable. On IPv4-only networks use the shared Supavisor session endpoint on port `5432` instead. Use the shared transaction endpoint on port `6543` for the stateless Vercel API after verifying it uses no named prepared statements or session-scoped state. Use a small client pool per runtime and verify TLS certificates and hostnames. Use the dedicated database roles in each connection and keep their credentials out of browser bundles and logs. [Endpoints and modes](https://supabase.com/docs/guides/database/connecting-to-postgres) · [Pooling limits](https://supabase.com/docs/guides/database/connecting-to-postgres/pooling-and-limits) · [TLS verification](https://supabase.com/docs/guides/platform/ssl-enforcement)
- **Vercel Hobby.** Published monthly allowances include 4 active CPU hours, 360 GB-hours of memory, and 1 million Function invocations. Hobby Functions have a 300-second limit, 2 GB RAM, and a 4.5 MB request and nonstreamed response limit. Keep synthetic files small and test streaming. Vercel Cron runs in production and permits each Hobby job at most daily within a one-hour window. Run the scheduler locally. Vercel deploys individual services and functions. Its runtime has no equivalent for Compose named volumes. [Hobby allowances](https://vercel.com/docs/plans/hobby) · [Function limits](https://vercel.com/docs/functions/limitations) · [Cron limits](https://vercel.com/docs/schedules/cron-jobs/usage-and-pricing) · [Compose comparison](https://vercel.com/i/can-you-run-docker-compose-on-vercel)
- **Supabase Free.** Published limits include two active projects, 500 MB database size per project, 1 GB of Storage, up to 50 MB per object, 5 GB egress, and 5 GB cached egress. Projects can pause after a week of inactivity. Check project availability and remaining allowances before recording. Free has no included automated backups. If an approved handoff needs a copy, export the database and files separately. [Plan allowances](https://supabase.com/pricing) · [File size limit](https://supabase.com/docs/guides/storage/uploads/file-limits) · [Backup coverage](https://supabase.com/docs/guides/platform/backups)

## Approval and recording

Run the complete application build, lint, and tests locally first. Obtain explicit authorization before creating projects, connecting accounts, uploading source, triggering hosted CI, or deploying. A publishable source baseline does not authorize hosting the runtime or uploading data. After approval, a CLI deployment of the reviewed revision is an option without Git integration. Hobby Git integration cannot deploy a private GitHub organization repository. [Vercel CLI deploy](https://vercel.com/docs/cli/deploy) · [Hobby Git restrictions](https://vercel.com/docs/git#using-hobby-teams)

Before recording, verify unauthenticated access fails for all deployment URLs, the app rejects unauthorized downloads, and a synthetic run still completes once the local worker restarts. Check evidence, CSV downloads, and quota status with the exact hosted configuration.

Call `GET /api/v1/records` with both credentials and a `records:read` key. Expect only authorized synthetic records with suppressed fields omitted. Repeat through the local bridge with `search_records`. With the Skyscrape key alone, expect a Vercel challenge. With the Vercel token alone, expect an app authentication error. With a valid Skyscrape key lacking `records:read`, expect an app scope error. Keep recorded evidence free of authorization headers. These hosted checks are pending. The recording is separate from the qualified live source, independent review, and restore evidence in [PLAN.md](../PLAN.md).

After recording, wait for separate deletion instructions. On authorization, stop the demo worker, revoke demo credentials, and delete the dedicated Vercel and Supabase projects. Supabase project deletion also removes its database, Storage objects, and backups. Verify the former URLs no longer serve the demo.
