# Lanes binding for Skyscrape

The installed Lanes package reports **0.6.1** in `lanes/VERSION`. The source checkout identifies revision `0311346dc6debf263def07be83399fe4f5c00949` and a proprietary license in `lanes/LICENSE`. The Codex and source installations have identical `lanes/SKILL.md` content. Paths below are relative to the skill installation. In command examples, `$K` is its root and `$S` is the project-specific Lanes state directory. These are documented operations for the orchestrator. No service or release has been qualified.

| Operation | Project binding | Installed authority at the revision above |
| --- | --- | --- |
| Start | The Codex chat instruction is `$lanes start`. Reconcile instructions, branches, unfinished work and Beads using `bd ready` and `bd list`. Resolve state with `S=$(. $K/lane/lane-env.sh; lanes_state)`. The Markdown handoff supplies context. | `lanes/SKILL.md` opening and §1, `lanes/CODEX.md` session start, `project-kickoff/references/handoff.md` v0.7.0 |
| Register work | Beads retains the existing WP identities and blocking edges. Use the plan and §13 of its companion for acceptance and boundaries. The orchestrator writes the task brief and open-lane registry row in `$S/lanes.tsv`. | `lanes/SKILL.md` §§1,3, `lanes/rules/brief-template.md` |
| Dispatch | Only the main orchestrator dispatches. Use DEC-004 and DEC-005 for participants, model selection and independent review. Check the selected route supports the requested settings before dispatch. | `lanes/CODEX.md` model routing, `lanes/SKILL.md` §§2–3 |
| Isolate | Create a linked worktree with `bash "$K/lane/new-worktree.sh" <branch> [base]`. State exact owned paths and one writer for each shared contract, migration or lockfile. Delegate documentation and bootstrap too. | `lanes/SKILL.md` §3, `lanes/rules/COLLECTION.md` |
| Review | Collect the scoped payload into a fresh round with `bash "$K/lane/collect.sh" "$S/lanes/<lane>/r<N>" <branch>`. Dispatch a separate cross-model reviewer with the base, scope and checks. FIX applies to a P1/P2, failed scope or failed check. Remediate in the assigned worktree and review the revised commit. | `lanes/rules/COLLECTION.md`, `lanes/rules/REVIEW_RULES.md`, `lanes/CODEX.md` |
| Recover | Beads owns task status. Lanes stores the brief, evidence and verdict beside its registry. Preserve the PAUSED note, revision, dirty work, next action and session checkpoint. Resume in the same worktree after reconciling recorded progress. | `lanes/SKILL.md` §§1,5,7 |
| Integrate | Only the integrator runs `bash "$K/lane/lane-finish.sh" "$S/lanes/<lane>/r<N>" <branch>` when authorized under the project's publication restrictions. Return a conflict to the lane for rebase and review. Preserve prior revisions and evidence for rollback. | `lanes/SKILL.md` §4, `lanes/CODEX.md` integration |
| Preview and release | WP13 requires independent evidence, private preview and recovery verification. The project's external-action restrictions govern every release step, including any automatic push behavior in the finish helper. | `lanes/SKILL.md` §§4,6 and implementation plan §§11–13 |
| Repair | The runtime prepares a sanitized local repair brief. The orchestrator reconciles it with an existing Beads item or records a new repair there, then dispatches a scoped task. Connector changes require independent verification, canary evidence and a rollback path. | `lanes/SKILL.md` §§1,3–4, `lanes/rules/brief-template.md` and implementation plan §10 |
| Complete | Collect exact owned paths, acceptance commands, evidence report and a single-line commit subject. Match verdict and evidence to the collected revision. The integrator records the result in Beads after verification. | `lanes/rules/COLLECTION.md`, `lanes/rules/REVIEW_RULES.md`, `lanes/SKILL.md` §4 |
